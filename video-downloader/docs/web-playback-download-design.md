# 웹 재생 다운로드 설계

## 목적

일반 웹사이트에서 사용자가 재생 버튼을 누른 뒤 광고가 끝나고 본편이 시작되는 경우,
본편의 HLS/DASH 요청을 사용자가 명시적으로 확정하여 다운로드한다. 이 기능 때문에 기존
YouTube, 직접 URL, 정보 확인, 자동 폴백, 일괄 다운로드의 동작이 바뀌지 않아야 한다.

## 설계 원칙

1. 웹 재생 다운로드는 전역 설정이 아니라 단일 다운로드 화면의 별도 실행 명령이다.
2. 기존 `다운로드` 버튼과 Enter 키는 지금과 같은 yt-dlp 우선 경로만 시작한다.
3. 기존 `browser_capture.enabled`는 직접 추출 실패 후 자동 폴백이라는 현재 의미를 유지한다.
4. 정보 확인과 일괄 다운로드에는 웹 재생 우선 경로를 연결하지 않는다.
5. YouTube와 DRM 콘텐츠는 UI와 엔진 양쪽에서 차단한다.
6. 사용자가 본편 시작을 확인하기 전에는 캡처 후보를 다운로드하지 않는다.
7. 기존 쿠키 범위 제한, 임시 프로필 삭제, 취소 처리를 그대로 적용한다.

## UI

단일 다운로드 버튼 행을 다음과 같이 구성한다.

```text
[정보 확인]  [웹 재생으로 다운로드]  [다운로드]
```

- `다운로드`는 기존 기본 버튼이며 동작을 변경하지 않는다.
- `웹 재생으로 다운로드`는 일반 웹사이트에서만 사용하는 보조 버튼이다.
- URL 입력 후 Enter를 누르면 기존 `다운로드`가 실행된다.
- 캡처 브라우저 선택은 `웹 재생 브라우저`라는 이름으로 항상 선택 가능하게 한다.
- `일반 분석 실패 시 브라우저에서 영상 주소 찾기` 체크박스는 기존 자동 폴백만 제어한다.

웹 재생 작업이 시작된 동안에만 작업 상태 영역에 다음 임시 제어를 노출한다.

```text
브라우저에서 영상을 재생하세요. 광고가 있으면 본편이 시작될 때까지 기다리세요.
[본편 재생 중]  [취소]
```

- 브라우저가 준비되기 전에는 `본편 재생 중` 버튼을 비활성화한다.
- 사용자가 버튼을 누르면 다시 누를 수 없게 하고 `본편 미디어 확인 중...`으로 표시한다.
- 완료, 실패 또는 취소 시 임시 제어를 숨기고 기존 작업 상태 화면으로 복귀한다.
- YouTube URL에서 웹 재생 버튼을 누르면 브라우저를 열지 않고 `YouTube는 일반 다운로드를
  사용하세요.`라고 안내한다.

## 기존 경로와 격리

| 진입점 | 실행 경로 | 변경 여부 |
|---|---|---|
| 정보 확인 | `ProbeThread -> engine.probe` | 없음 |
| 다운로드/Enter | `DownloadThread -> build_download_engine` | 없음 |
| 자동 브라우저 폴백 | 직접 추출 실패 후 `BrowserFallbackEngine` | 의미 유지 |
| 일괄 다운로드 | `BatchThread -> BatchService` | 없음 |
| 웹 재생으로 다운로드 | 전용 `WebPlaybackDownloadThread` | 신규 |
| CLI | 기존 옵션과 동작 | 없음 |

명시적 웹 재생 경로는 `Settings.browser_capture.enabled` 값을 변경하거나 요구하지 않는다.
따라서 자동 폴백을 꺼 둔 사용자도 한 번의 웹 재생 작업을 실행할 수 있고, 그 선택이 다음
작업이나 일괄 다운로드에 남지 않는다.

## 컴포넌트 변경

### URL 정책

현재 `fallback.py`에 있는 YouTube 호스트 판정을 공용 함수로 옮긴다. UI는 빠른 안내에
사용하고 엔진은 최종 방어선으로 다시 검사한다. 최소 차단 대상은 `youtube.com`의 모든
하위 도메인, `youtu.be`, `youtube-nocookie.com`의 모든 하위 도메인이다.

### 전용 작업자

`WebPlaybackDownloadThread`를 추가하고 기존 `DownloadThread`는 수정하지 않는다. 전용
작업자는 다음 신호와 명령을 제공한다.

- `browser_ready`: 임시 브라우저가 열리고 네트워크 감시가 시작됨
- `status_changed`: 광고 대기, 후보 확인, 다운로드 상태
- `confirm_main_content()`: 사용자 확인 이벤트 설정
- 기존 `cancel()`: 확인 대기, 브라우저 및 yt-dlp 프로세스를 모두 중단

사용자 확인은 `threading.Event`로 전달한다. GUI 스레드는 이벤트만 설정하고 Selenium이나
다운로드 코드를 직접 호출하지 않는다.

### 명시적 캡처 엔진

기존 `BrowserFallbackEngine`의 실행 순서를 바꾸지 않는다. 별도
`BrowserCaptureDownloadEngine`이 다음 순서를 담당한다.

```text
원본 URL 정책 검사
  -> 임시 브라우저 시작
  -> 사용자가 재생하고 본편 시작 확인
  -> 본편 후보 선택
  -> 범위가 제한된 쿠키와 요청 헤더 생성
  -> 기존 YtDlpProcessEngine으로 다운로드
  -> FFprobe 결과 반환
```

캡처 결과를 yt-dlp 작업으로 바꾸는 쿠키·헤더 처리 코드는 두 엔진이 공유하는 작은 내부
함수로 추출한다. 기존 폴백 테스트를 먼저 고정한 뒤 기계적으로 추출하여 동작 변경을
막는다.

`DownloadEngine` Protocol과 `Job`에는 캡처 우선 플래그를 추가하지 않는다. 전역 엔진
계약이나 일괄 처리 모델로 새 실행 방식이 누출되는 것을 방지하기 위해서다.

## 광고와 본편 후보 선택

현재의 `첫 후보 발견 후 grace_seconds가 지나면 종료` 규칙은 자동 폴백에 그대로 둔다.
명시적 웹 재생 작업에만 사용자 확인 기반 수집 정책을 사용한다.

각 후보에 최초 발견 시각, 마지막 발견 시각, 발견 순서와 광고 힌트 여부를 기록한다.

1. 사용자 확인 전까지 모든 HLS/DASH 후보를 수집한다.
2. URL에 알려진 광고 표식이 있으면 광고 후보로 표시하지만 즉시 실패하지 않는다.
3. `본편 재생 중` 확인 뒤 짧은 안정화 시간 동안 새 요청을 계속 수집한다.
4. 광고 표식이 없는 후보 중 확인 시점과 가장 가까운 최신 후보를 우선한다.
5. master playlist를 같은 시점의 variant playlist보다 우선한다.
6. 광고 후보밖에 없으면 광고를 다운로드하지 않고 본편을 찾지 못했다는 오류를 반환한다.

URL 표식만으로 광고를 완벽하게 판별할 수 없으므로 사용자 확인 시점이 주 판단 기준이다.
자동으로 재생 버튼을 클릭하거나 광고를 건너뛰지는 않는다.

DRM 라이선스 또는 manifest 신호가 하나라도 발견되면 기존 정책처럼 즉시
`DRM_PROTECTED`로 중단한다. 광고 자체가 DRM인 경우에도 우회를 시도하지 않는 안전한
실패를 선택한다.

## 시간 제한과 취소

- 브라우저 시작 제한과 전체 사용자 대기 제한을 구분한다.
- 명시적 웹 재생의 전체 대기는 기본 180초로 하고 설정에서 조정할 수 있게 한다.
- 확인 뒤 후보 안정화 시간은 기존 `grace_seconds`를 재사용한다.
- 제한시간, 창 닫힘, 사용자 취소는 서로 다른 안내 문구를 반환한다.
- 모든 종료 경로에서 WebDriver, 임시 프로필과 임시 쿠키 파일을 정리한다.

자동 폴백의 기존 제한시간 기본값과 동작은 변경하지 않는다.

## 단계별 구현 순서

### 1. 기존 동작 고정

- 기존 일반 다운로드, YouTube 차단, 자동 폴백, 일괄 처리 테스트를 회귀 기준으로 고정한다.
- 공용 URL 정책과 캡처 결과 전달 함수를 추출한 뒤 기존 테스트가 그대로 통과하는지 확인한다.

### 2. 명시적 캡처 도메인 계층

- 시간 정보가 있는 후보 모델과 사용자 확인 이벤트를 추가한다.
- 광고 후 본편, 광고 없는 본편, 광고 후보만 존재, 제한시간, 취소, DRM을 단위 테스트한다.
- `BrowserCaptureDownloadEngine`을 추가하고 원본 URL을 먼저 직접 다운로드하지 않는지 확인한다.

### 3. GUI 연결

- 단일 화면에 웹 재생 버튼과 실행 중에만 나타나는 확인 버튼을 추가한다.
- YouTube 안내, 중복 클릭 방지, 작업 중 버튼 상태와 종료 후 복원을 테스트한다.
- 정보 확인, Enter 다운로드와 일괄 다운로드가 기존 작업자를 계속 사용하는지 테스트한다.

### 4. 실제 검증

- 광고 없는 로컬 HLS 페이지
- 광고 manifest 뒤 본편 manifest가 요청되는 로컬 페이지
- 공개 YouTube 일반 다운로드
- 직접 MP4와 일반 HLS/DASH 다운로드
- 기존 실패 후 자동 브라우저 폴백
- 취소와 제한시간, DRM 모의 페이지

## 회귀 방지 완료 기준

- 기존 자동 테스트가 모두 통과한다.
- 일반 다운로드를 누르면 캡처 객체가 생성되지 않는다.
- YouTube 웹 재생 요청은 WebDriver 생성 전에 거절된다.
- 일괄 다운로드는 명시적 웹 재생 작업자를 참조하지 않는다.
- 광고가 있는 페이지에서 광고 URL이 결과로 선택되지 않는다.
- 광고가 없는 페이지는 동일한 확인 흐름으로 다운로드된다.
- 사용자 확인 전에는 어떤 캡처 후보도 yt-dlp로 전달되지 않는다.
- 다운로드 화질 선택과 FFprobe 결과 표시는 기존과 동일하게 적용된다.
- 성공, 실패, 취소 후 임시 프로필과 쿠키 파일이 남지 않는다.

## 제외 범위

- 사이트별 광고 건너뛰기 또는 자동 클릭
- DRM 우회
- YouTube 네트워크 캡처
- 웹 재생 방식의 일괄 다운로드
- 개인 브라우저 프로필을 Selenium 임시 브라우저에 직접 연결
- 이번 단계의 CLI 캡처 우선 옵션
