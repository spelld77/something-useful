# 일괄 다운로드 진행 상태 설계

## 목표

일괄 작업의 전체 처리 상태와 현재 파일의 다운로드 상태를 혼동하지 않도록 분리한다. 성공 여부와 처리 완료 여부도 분리해, 일부 항목이 실패해도 목록을 끝까지 검사했다면 전체 진행률은 100%로 표시한다.

## 상태 전달

`BatchService`는 기존 항목 시작 콜백과 다운로드 진행률 콜백에 더해 항목 완료 이벤트를 보낸다. 완료 이벤트 상태는 `SUCCEEDED`, `FAILED`, `SKIPPED`, `CANCELLED` 네 가지이며 인덱스, 전체 개수, 원본 URL과 선택적인 `DownloadResult`를 포함한다.

`BatchThread`는 서비스 콜백을 Qt 신호로 전달하고 GUI는 다음 상태를 별도로 유지한다.

- 현재 항목: 인덱스, 파일 진행률, 속도, 남은 시간
- 전체 작업: 처리된 항목 수, 성공, 실패, 건너뜀, 취소
- 종료 요약: 취소 시 현재 취소 항목과 아직 시작하지 않은 항목

전체 진행률은 작업 중 `(처리된 항목 + 현재 파일 진행률) / 전체 항목`으로 계산한다. 작업이 취소되지 않고 모든 항목을 검사했다면 성공·실패 구성과 관계없이 100%로 확정한다.

## 로그와 보안

항목 로그에는 URL의 호스트와 경로만 표시한다. 사용자 정보, 쿼리와 조각 식별자는 표시하지 않는다. 오류 메시지에는 기존 민감정보 마스킹을 한 번 더 적용한다. 원본 URL은 실패 재처리 파일처럼 기능상 필요한 저장소에만 기존 정책대로 기록한다.

## 오류와 취소

예상하지 못한 항목별 예외는 `UNKNOWN` 실패로 변환해 기록하고 다음 항목을 계속 처리한다. 사용자가 현재 다운로드를 취소하면 해당 항목을 `CANCELLED`로 세고 이후 항목은 `unprocessed`로 남긴다. 항목 사이 대기 중 취소하면 새 항목을 취소로 세지 않고 남은 항목 전체를 `unprocessed`로 둔다.

## 기존 기능 보호

단일 다운로드와 명시적 웹 재생 다운로드는 기존 진행 막대를 그대로 사용한다. 전체 진행 UI는 `BatchThread`에서만 표시되며, 브라우저 자동 캡처 설정이 켜진 일괄 작업은 실패 항목에서 브라우저가 열릴 수 있음을 시작 로그에 안내한다.
